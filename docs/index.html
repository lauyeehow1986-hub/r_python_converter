Convert Python Packages into Standalone Native R Packages

pyport parses and transpiles Python source files, wheels (.whl), and source distributions (.tar.gz) into standalone R packages (.tar.gz source tarballs and Windows .zip / macOS .tgz binaries) backed by pyrt—with no Python installation, no reticulate, no virtualenv, and no PATH changes.

Why pyport + pyrt?

1. Zero Python Dependency

Neither converting a package (pyport::convert()) nor running the converted R package requires Python on the machine. Parsing is powered by a vendored tree-sitter-python v0.23.6 C grammar.

2. Exact Python Semantics in R

pyrt provides reference-semantics containers (py_list, py_dict, py_set), 0-based negative/step slicing, C3 MRO classes, CPS generators, gmp::bigz arbitrary-precision integers, and bit-exact CPython random & NumPy PCG64 / MT19937 in C.

3. Native C, Cython, & Rust Bridges

Automatically bridges <Python.h> C extensions (PyMethodDef, PyArg_ParseTuple), Cython cdef/cpdef functions, and Rust PyO3 (#[pyfunction], #[pyclass]) to R's C API and extendr.

Quick Start

library(pyport)
library(pyrt)

# 1. Evaluate Python code directly in R (no Python installed!)
env <- eval_python("
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
")
env$fib(10L)
#> [1] 55
env$fib(100L)
#> Big Integer ('bigz') :
#> [1] 354224848179261915075

# 2. Convert a Python package into a standalone R package + Windows .zip binary
res <- convert("corpus/more-itertools", file.path(tempdir(), "more.itertools"))
built <- build_r_package(res$path, dest_dir = tempdir(), binary = TRUE)
# Produces more.itertools_10.5.0.tar.gz and more.itertools_10.5.0.zip!
